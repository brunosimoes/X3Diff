A shared language for
3D on the web.

X3D brings interactive scenes to the open web. Developed by the Web3D Consortium, it is an open, royalty-free ISO standard for representing and sharing 3D content—from geometry and appearance to animation and interaction.

X3Diff builds on that structured foundation: making scene revisions easier to inspect, discuss, and trust as Web3D experiences evolve.

A browser-based workbench for semantic and geometric review of X3D revisions.

6 MINUTE READ · PRINT FRIENDLY

What problem does this tool solve?

AI-assisted tools make it easier to create and modify digital content, including the scenes, scripts, and structured assets used in Web3D and metaverse applications. This shifts a practical bottleneck from producing a change to understanding it. A plausible-looking result is not enough to establish that an edit preserved the intended structure, dimensions, appearance, or behavior. Reviewers need to know what changed, where it changed, and which conclusions the available evidence supports.

For 3D scenes, neither a text diff nor a rendered image answers these questions alone. A text diff exposes edited values but separates them from their spatial effect. A rendered view makes the result visible but can conceal changes in references, defaults, or animation declarations. Small geometric changes can be hard to locate, while a conspicuous movement may come from a transform rather than a change in the underlying mesh. The gap between these representations makes acceptance decisions slower and harder to justify.

X3Diff addresses this gap with a local, interactive review workbench for two XML-encoded X3D 3.3 revisions. Its purpose is to support better decisions and review gates in workflows where edits may be authored by a person, generated by AI, or produced by another tool. It does not need to know how an edit was created. The comparison itself is deterministic and does not use an AI model.

How does it work?

The semantic layer parses a declared subset of X3D, resolves supported field defaults, and compares typed values with explicit tolerances. It reports changes to supported scene declarations, including geometry, transforms, materials, DEF/USE references, and ROUTEs. Unsupported or ambiguous content produces diagnostics rather than a trusted assertion that the scenes are equivalent. The result is a structured report that can be inspected in the interface and exported as JSON.

The visual layer places revisions in a common scene context and links selections to identifiable objects. Four analysis views provide complementary evidence. File differences presents the semantic register. Slice & measure intersects a supported object pair with a shared plane and provides a straight-line ruler. Surface deviation displays sampled nearest-surface distances in both directions. Volume differences isolates before-only, shared, and after-only regions for one supported matched pair.

These views are designed around practical questions rather than a single universal similarity score. A reviewer can locate an unexpected change, inspect a cross-section, examine a high-deviation face, and return to the underlying declaration. The tab registry makes views configurable and provides a small extension interface for additional analyses. Settings and layout choices are remembered in the browser.

How does it support gating?

A review gate is a decision point before a proposed revision is accepted, merged, or released. X3Diff supplies evidence for that decision: changed fields, spatial context, measurements with stated limits, and diagnostics that indicate when further investigation is necessary. For example, a reviewer can check whether an AI-assisted edit changed only the intended material or also modified a transform, then inspect any geometric effect before accepting the revision.

The acceptance criteria remain the responsibility of the project and its reviewer. X3Diff does not currently implement approval records, policy rules, automated pass/fail thresholds, or a CI merge gate. Its JSON report can serve as an input to a separately implemented review process. A clean report over supported declarations is not a certificate of complete X3D equivalence, physical validity, safety, or fitness for use.

What are its scope and contribution?

The tool runs as a static web application. User-selected models are read locally; no model-upload service or account is required. A Web Worker performs semantic comparison, while bounded geometry analysis and interactive renderers provide inspection views. Native X3D animation is demonstrated in the original revision views; geometric analysis examines authored static geometry rather than runtime motion.

Support is intentionally explicit. The semantic catalog covers 34 common X3D 3.3 nodes, not the entire standard. Surface distances are sampled at triangle centres; they are not exact continuous maxima. Volume calculations use tessellated primitives or a bounded sampled mesh approximation. Measurements use scene coordinates without automatic registration or unit conversion. Unsupported geometry and external scene content remain outside the analysis boundary.

The contribution is a reproducible connection between semantic review and spatial inspection: a reviewer can move from a reported change to geometric evidence while retaining the limits of that evidence. Automated tests cover parsing, comparison, known geometric cases, and browser interactions. Open source code, bundled examples, and documented extension points make the approach inspectable and reusable. The aim is to help people review increasingly rapid streams of changes with greater clarity and accountability.
